## 2. 总体技术决策

| # | 决策 | 选择 | 理由 |
| :--- | :--- | :--- | :--- |
| D1 | 默认语言与目录 | `values/strings.xml` 中文（默认资源）；`values-en/` 在 B7 机械补充 | 默认资源即现状；缺翻译回落中文不崩 |
| D2 | 语言来源 | **跟随系统语言**，不做应用内切换 | MainActivity 是 `ComponentActivity`、无 appcompat 依赖；应用内切换留作后续 |
| D3 | Compose 引用方式 | `stringResource(R.string.x, args…)`；带插值的转 `%1$s`/`%1$d` 占位符 | 标准做法 |
| D3b | ViewModel 文案 | 用户消息改 `UiMessage(@StringRes resId, args: List<String>)`，UI 层解析 | 不把 Context 塞进 VM，不碰 domain 零依赖铁律 |
| D4 | 通知/Receiver/DataExporter | `context.getString(R.string.x, args…)`；DataExporter 全程持有 Context（已核实），CSV 表头/状态值/导出文件名直接资源化 | 无争议 |
| D5 | 周几/日期标签 | 不进资源，`java.time.format.TextStyle` + `Locale.getDefault()` | 免费双语，删掉 ProgressViewModel 手写「今日/周一…」数组 |
| D6 | 命名规范 | `today_` / `cabinet_` … 按页面分组，`notif_`、`common_`、`csv_`、`note_`；占位符一律带位置 `%1$d` | 600 条必须有命名纪律 |
| D7 | **验收标准** | 中文界面无硬编码 UI 字符串（扫描器收敛到保留集：日志 1 条 + debug/test），中文全流程走查通过 | 英文翻译是后续机械批次，不阻塞本方案验收 |

## 3. 三个结构改造（全部做，v1 的妥协全部取消）

### D-A（P0）domain 层直接生成 UI 文案 → PauseStatus 结构化

`ReminderSettingsEntity.kt:105-107` 的 `pauseText()` 在 core/domain 里拼
「提醒已暂停，N 天后恢复」，domain 零 `android.*` 依赖拿不到 `Context.getString`。

**方案：** `pauseText()` 改返回结构化状态
`sealed interface PauseStatus { NotPaused; PausedIndefinitely; PausedUntil(days: Int?) }`
（放 domain model），展示点（MedicationDetail 徽标、TodayScreen 等）用 `when`
映射 `stringResource`。`MedicationOverview` 里「供 UI 直接显示的暂停说明」字段
（`MedicationOverview.kt:66`）一并结构化。同步改 `ReminderPauseTest`、
`MedicationOverviewTest`。**唯一动跨层契约的改动，独立成批（B4）。**

### D-B（P1）类别/剂型/时段标签以中文自由文本存库 → 稳定 key 化

现状：`AddEditMedicationViewModel` 的 `CATEGORIES/FORMS` 列表被选中后**原样写入**
`MedicationEntity.category / form`；`PolicyTimeEntity.label` 默认 `"服药时段"`；
`BackupFormat.kt:61,62,134` 恢复回填用同款中文默认值。

**方案（彻底 key 化）：**
1. 定义枚举 `MedicationCategory` / `MedicationForm`（Kotlin 侧唯一事实源，
   `name` 即入库 key，如 `COMMON` / `TABLET`），entity 字段改存 key。
   弃用中文字符串直存。删库重装，无迁移。
2. 显示名走资源：每个 key 一条 `category_common` / `form_tablet` …；
   下拉列表顺序用 Kotlin 枚举顺序驱动，不依赖 `string-array` 的顺序耦合
   （`string-array` 双语各写一份容易与枚举漂移，不用；`plural`/普通 string 足够）。
3. `BackupFormat` 默认值改 key（`category = "COMMON"` 等），备份 JSON 存 key，
   round-trip 测试同步更新（BackupFieldPreservationTest / BackupRoundTripTest）。
4. `PolicyTimeEntity.label`：同样是自由文本（「早餐前」「随早餐」「睡前」），
   改存 key 枚举 `SlotLabel`，显示名资源化；`AddEditMedicationViewModel` 的
   `TimeSlotDraft`、`MedicationAdminService` 的 `ifBlank { "服药时段" }`
   （`MedicationAdminService.kt:319`）、`ReminderSettingsViewModel.kt:494` 的
   label 拼装同步改。

### D-C（P2）流水备注 / CSV / 渠道名全量本地化

1. **流水备注 key 化。** `DoseTrackingService`（domain 层）里 10+ 处程序化默认
   备注（`note ?: "按时服药打卡扣减"`、`"主动跳过本次服药"`、
   `"用户误触打卡撤销冲正"`、`"库存盘点校准 (账面 X → 实物 Y)"` …）全是硬编码
   中文，domain 拿不到 Context。**方案：`InventoryTransactionEntity` 加
   `noteKey: String?` 列（稳定 key，如 `TAKE_DEDUCT` / `SKIP` / `CALIBRATE`），
   `note` 列只存用户自由文本**；展示处（流水列表 UI、CSV 导出）按 key 映射
   `note_take_deduct` … 资源，带参数的（盘点校准的账面/实物）从流水既有字段
   （amount、账面值）在展示层拼装；key 与自由文本并存时优先按 key 显示。
   无 noteKey 且 note 非空的，原样显示（用户输入）。
   **不再把「中文备注」当数据写库**——这是 v1 被否掉的妥协，取消。
2. **CSV 导出资源化。** DataExporter 已持有 Context（已核实），表头
   （「服药时间,药品名称,…」）、状态列值（「已服(补录)」「跳过」「已撤销」）、
   导出文件名（`CarroMed_服药明细_`、`CarroMed_库存流水_`、`CarroMed_全量备份_`、
   `CarroMed_恢复前快照_`、`CarroMed_诊断日志_`）、`importBackup` 的错误消息
   （`"无法读取所选文件"`）全部 `context.getString`。CSV 里由 D-B/D-C-1 key 化
   后的枚举值同样经 `csv_` 资源映射输出。
3. **通知渠道名资源化。** 渠道名/描述从资源读。已知平台事实：渠道名一经创建
   不可改名，切语言不更新已存在渠道；开发期删库重装即可，发布后接受的残留
   风险记入 §5。

## 4. 分批实施

每批独立可编译（debug+release）、单测全绿、走查通过后进下一批。
AGENTS.md 验收标准全程适用。

### B1 基建 + 机械抽取（~510 条）

1. 建 `values/strings.xml`（中文默认）。
2. 14 个 Screen + AppNavigation 底部导航：`Text("今日")` →
   `Text(stringResource(R.string.today_title))`。
3. 通知层（Notifications / DoseActionReceiver / AlarmScheduler）：
   `context.getString(...)`。

### B2 ViewModel 用户文案（~145 条）

1. Snackbar/Toast、校验报错改 `UiMessage(resId, args)`（D3b）。
2. 全部插值转 `%1$s`/`%1$d` 占位符——本项目插值多，是本批主要工作量。
3. 排序选项、周期标签（过去 7 天/30 天/1 年）进资源；星期标签按 D5 改
   `DateTimeFormatter`。

### B3 结构改造一：类别/剂型/时段标签 key 化（D-B）

枚举 + entity 字段改 key + 显示资源化 + BackupFormat 默认值改 key +
AddEdit/AdminService/ReminderSettings 相关拼装逻辑同步。
涉及测试：BackupFieldPreservationTest、BackupRoundTripTest、
AddEditLogicTest、MedicationAdminServiceTest、FieldPreservationInvariantTest。
**改完删库重装验证。**

### B4 结构改造二：PauseStatus（D-A）

`pauseText()` → `PauseStatus`，改 MedicationDetail/Today 展示点，
同步改 ReminderPauseTest、MedicationOverviewTest。

### B5 结构改造三：流水备注 key 化 + CSV 资源化（D-C）

1. `InventoryTransactionEntity` 加 `noteKey` 列（schema 变更，删库重装）；
   DoseTrackingService 全部程序化默认备注改 key；自由文本路径保持。
2. 流水展示处（Inventory/Refill/RecordDetail 相关 UI）按 key 映射资源。
3. DataExporter CSV 表头/状态值/文件名/错误消息资源化。
涉及测试：AppendOnlyFactTableTest、InventoryLedgerInvariantTest、
UndoRoundTripLedgerTest、BackupRoundTripTest（备份含流水）、DataExporter 相关。

### B6 测试收口 + 扫描收敛验收（中文标准）

1. SmokeNavigationTest 中文断言改 `R.string` 引用；测试统一
   `Locale.setDefault(Locale.SIMPLIFIED_CHINESE)`（Robolectric 默认 en_US，
   默认资源是中文，必须显式固定）；快照测试同样固定 locale。
2. 重跑 `scan_hardcoded_strings.ps1`：main 收敛到保留集（纯日志 ~1 条），
   把最终扫描结果存档。
3. 中文全流程走查：今日 → 详情 → 编辑 → 提醒设置 → 库存/补货 → 手动补录 →
   统计 → 设置 → 备份导出/恢复 → 通知三个 Action → 暂停徽标。走查前删库重装。

### B7（后续机械批次）values-en 翻译 + 双语走查

按 `values/strings.xml` 全量翻译 `values-en/`；模拟器系统语言切英文复跑 B6
走查清单 + 截图看图。此后加任何语言 = 新增 `values-xx/` 翻译文件，纯机械。

## 5. 风险与对策

| 风险 | 对策 |
| :--- | :--- |
| 600 条逐条替换，漏改/错改 R.string | 每批结束重跑扫描脚本，数量单调下降并收敛到保留集（D7） |
| key 化改动面大（B3/B5 动 entity + 备份 + 多个 Service） | 每批内先改枚举与 entity，再改调用点，最后改测试；单测锁 round-trip；删库重装实测 |
| 英文比中文长 30-60%，布局溢出 | B7 双语走查看图；PermissionCheck 长句翻译时主动拆句 |
| Robolectric/快照测试断言中文文本失败 | B6 统一固定 locale；断言尽量改 testTag |
| 通知渠道名切语言不更新（平台限制） | 开发期重装即解决；发布后旧渠道名残留，记为已知限制（渠道 id 不变，行为不受影响） |
| 流水 noteKey 与自由文本并存的显示歧义 | 显示优先级固定：有 key 显示 key 资源；无 key 显示原文本；key 枚举收口在一处定义 |
