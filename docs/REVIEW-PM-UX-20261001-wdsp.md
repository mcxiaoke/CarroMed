## 一、总体评价

### 做得好的（应当保持）

- **数据骨架是同类产品里少见的严谨**：规则→槽位→事实三层时序解耦、库存事件溯源（`SUM(change_amount) == 余额`）、局部 UPDATE 防整行覆盖，这三条不变量直接决定了"记录真实"承诺的可信度，420 项真库单测是扎实背书。
- **打卡闭环完整**：打卡/撤销（反向冲正流水）/跳过（不扣库存不污染分母）/推迟/补录齐全，且"跳过独立成区""分母为 0 显示 — 不制造虚假满分"这类反虚荣设计很成熟。
- **今日页信息密度控制得当**：待服/已服/已跳过三区分离、库存告警横幅、未来日只读预览，符合"状态先行、无压迫感"的设计原则。
- **诚实文案意识好**："另有 N 次尚未到服药时间，未计入依从率"（统计页）、"尚未设置服药计划，点击设置"（详情页空计划提示）都避免了虚假保证。

### 一句话结论

**内核（数据与提醒可靠性）已达到甚至超过业界水准，但"最后一公里"的产品完整度和交互打磨存在系统性欠账**：FINAL-PRODUCT 里已拍板的多个 P0/P1 决策未落地（Onboarding、锁屏隐私三档、合并通知、准时率），今日页缺少与第一承诺直接相关的提醒健康状态入口，且 UI 走查脚本当前对近半数页面已失效——"亲眼看图"这条验收线事实上处于失守状态。

## 二、业务逻辑问题（PM 视角）

按严重程度排序。标注【新增】的是既有 review 文档未覆盖的本轮新发现。

### B-1【新增·高】今日页没有"提醒健康"入口，第一承诺对用户不可见

- **证据**：`TodayScreen.kt` 全文无任何提醒降级/权限异常的横幅或徽标；FINAL-UI §四 规划的"健康徽标（绿=提醒链路正常/黄=降级中）"未实现。降级档位只在 `PermissionCheckScreen`（入口藏在设置页二级按钮里）可见。
- **为什么重要**：产品第一承诺是"到点一定响"。但用户唯一能确认"提醒还活着"的方式是主动翻进设置→保活指引。用户从通知渠道被关、电池优化被 ROM 重置，到发现漏提醒之间，App 没有任何主动示意。**可靠性如果不可感知，等于不可信。**
- **建议**：在今日页右上角恢复健康徽标（`AlarmScheduler.currentPrecision` + 通知权限 + 电池白名单三态聚合），降级时点击直达自检页；降级状态下首次打开 App 弹一次性说明。

### B-2【高】手动补录不回填槽位，依从率对用户"说谎"（OPEN-ISSUES D1，催促拍板）

- **证据**：`DoseTrackingService.logManualDose` 只写 `slot_id = null` 的独立事实。用户昨天漏打卡、今天补录，依从率里这次仍算"漏服"。
- **用户视角**：我明确告诉 App"我吃了"，统计却说我没吃——这与"记录真实"的承诺直接冲突。业界（MyTherapy/Medisafe）补记一律计入当天实际服用。
- **建议**：尽快拍板 D1。推荐语义 1（补录命中当日/临近的开放或过期槽位并绑定），并把补录页文案区分"补打卡"与"额外吃了一次"两种情况。

### B-3【新增·中】Streak 断签规则过苛：主动跳过直接清零

- **证据**：`StatsEngine.calculateStreak`（`StatsEngine.kt:347-398`）单日达成标准要求 `missed == 0 && skipped == 0`——医嘱要求的跳过（如"今天验血空腹停一次"）也会清零连击。
- **对照业界**：MyTherapy 的 streak 鼓励"连续完成任务"，跳过不惩罚；Cadence 等 ADHD 向产品明确要求"forgiving framing——单次缺席不应触发全有全无心理"。
- **为什么重要**：跳过是用户**主动、正确**的行为，被系统当失败惩罚，会产生"反正 streak 已断"的破罐心理，与依从性目标背道而驰。
- **建议**：主动跳过不断签（或提供"补上"机会），仅漏服断签；徽标在 0 天时弱化显示（见 U-2）。

### B-4【新增·中】通知推迟只有固定一档，与规范和竞品不符

- **证据**：`Notifications.kt:185` 通知 Action 只有一个"推迟 N 分钟"（N = 当前生效配置）；FINAL-PRODUCT M-03 与 FINAL-UI §十一 均规划"推迟 30m / 推迟 1h"两档。通知上不可选档（记录详情页倒是有 10/15/30/60/120 档）。
- **场景**：药到点时正在开会，用户想"推迟 1 小时"而不是当前配置的 15 分钟，在通知上做不到，必须解锁进 App。
- **建议**：通知提供两个推迟 Action（默认档 + 长档），代价极低。

### B-5【新增·中】设置页缺"提醒铃声与震动模式"，提醒可感知性单一

- **证据**：FINAL-UI §八 规划"提醒铃声与震动模式（跟随系统/温和药铃/强提醒急促音）"；`SettingsScreen.kt` 通知分组只有推迟时长 + 夜间免打扰。现状所有提醒共用系统默认声。
- **对照业界**：Medisafe 把"12+ 种提醒音"当卖点；老人用户对"能听出是吃药铃"的依赖很强。
- **建议**：至少提供 2-3 档提示音 + 震动模式开关，挂独立通知渠道即可（渠道重要性机制已具备）。

### B-6【低】导出物面向"机器"而非"医生"

- **证据**：导出仅 CSV（服药明细/库存流水）与 JSON 全量备份。竞品标配是"可分享给医生看的报告"（MyTherapy PDF 健康报告、Medisafe logbook）。
- **现状影响**：目标用户"慢病患者复诊"场景下，CSV 对医生和老人都不友好。
- **建议**：v2 考虑从统计模块派生一页式"用药摘要"（图片或 PDF），复用现有 StatsEngine 数据，无需新模型（FINAL-PRODUCT §九 已论证过此扩展路径）。

### B-7【低】默认排序对老用户不友好

- **证据**：`CabinetViewModel.CabinetSortOrder.DEFAULT` 为 id 倒序（最新添加的在前）。药品一多，"天天吃的那个药"会越排越靠下。
- **建议**：默认排序改为"常用优先"（有 active policy 的在前、按下次提醒时间），或至少记住用户上次选择。

## 三、UI/UX 问题（设计师视角）

### U-1【新增·高】今日页 FAB 文案"添加"是歧义文案

- **证据**：`strings_today.xml:3-4`，`today_manual_log` = "添加"；点击行为是跳转**手动补录服药**页（`TodayScreen.kt:144-152`）。同屏还有：首启空态 CTA"添加药品"（那是去添加药品的）、统计页无添加入口、药箱页"+"才是添加药品。
- **危害链**：
  1. 用户在今日页想加药 → 点"添加" → 落到补录表单，困惑；
  2. 进展页空态文案"在今日清单点「添加」可记录临时用药"（`strings_prog.xml:9`）进一步固化这个歧义叫法；
  3. 老人用户几乎不可能理解"添加"在今日页=补录、在药箱=加药。
- **建议**：FAB 文案改"记服药"或"补录"（补录语义在 README 里本来就是这么写的），与药箱"添加药品"严格区分。

### U-2【新增·高】Streak 徽标三重问题：歧义、兼任隐藏入口、0 天负激励

- **证据**：今日页右上角"★ 0 天"徽标（`TodayStreakBadge.kt`）：
  1. **含义不可知**——新用户无从知道"天"指连续全勤服药天数，且 0 天时仍醒目展示一个零分成绩；
  2. **兼任月历入口**——点它会弹出 `DoseHistoryCalendarSheet` 月历（`TodayScreen.kt:136-140`），这是全 App 唯一的月历入口，却伪装成一个成绩徽标，可发现性极差（月历热力图在 FINAL-PRODUCT M-06 里是 P0）；
  3. 与 B-3 叠加，0 天徽标天天提醒用户"你断签了"。
- **建议**：徽标与月历入口拆开——月历改为日期条旁的显式日历图标；streak ≥ 2 才显示，0/1 天不显示或灰显；徽标加语义化 contentDescription。

### U-3【新增·高】"服药建议 / 服药时段 / 服药与用餐关系"三个名字指向同一个字段

- **证据**：提醒设置页下拉框 label 为"服药建议"（`strings_rem.xml:67`），默认选项显示"服药时段"（`strings_vocab.xml:25`），而枚举真实语义是"服药与用餐关系"（饭前/随餐/饭后/空腹/睡前，`SlotLabel`）。截图 `14_med_reminder.png` 中"label=服药建议、值=服药时段"同框出现，用户无法建立"这个选项管的是饭前还是饭后"的认知。
- **建议**：统一叫"服用时间"，选项值为"空腹/饭前/随餐/饭后/睡前/不限"；删掉"服药时段"这个占位叫法。

### U-4【新增·高】详情页"近 30 天用药"显示"暂无计划"，与同页"提醒设置：每天 1 次"自相矛盾

- **证据**：截图 `12_med_detail.png`：提醒设置行显示"每天 1 次 · 13:30 · 无限期"，下方"近 30 天用药"卡片却显示"暂无计划"。代码层面：`MedicationDetailScreen.kt:846-861`，"暂无计划"的判据是 `decided == 0`（近 30 天没有已决槽位），而非"无计划"（`policy != null`）。计划刚建、起始日未到、或槽位未投影时都会误标。
- **建议**：`decided == 0` 时显示"近 30 天暂无打卡记录"（或区分"计划尚未开始/尚无数据"），"暂无计划"仅在 `policy == null` 时使用。

### U-5【新增·高】UI 走查脚本锚点大面积失效，"亲眼看图"验收线失守

- **证据**：`temp/appscreenshots/manifest.md`（2026-09-30 21:10）：**23 条断言失败**；`07_manual_dose`、`08_settings`、`09_permission_check`、`16_refill`、`17_progress`、`18_progress_timeline`、`19_med_history` 七组截图实际内容全是今日页。根因是文案改动后脚本锚点未同步：底部 tab"进展"已改名"记录"（`strings_nav.xml:5`，脚本 `TABS=("今日","药箱","进展","统计")`）、页面标题"今日清单"已改"今日用药"、FAB desc"补录"已改"添加"等。
- **危害**：AGENTS.md 把"亲自看过图"列为验收硬标准，但目前一半页面**没有有效截图**，README 的"13 个全屏页面全部实测通过"声明已过期。这正是 AGENTS.md 警告的"编译过+单测绿覆盖不到界面接线"的复发。
- **建议**：立即修脚本锚点并重跑全量走查；把"manifest 断言 0 失败"加入改动涉及界面时的完成定义；走查锚点尽量绑定 `testTag` 而非可见文案（`TestTags.kt` 已有基础设施）。

### U-6【新增·中】药箱卡片无"今日服药状态"，用户需来回切换核对

- **证据**：`CabinetScreen.kt:287-420` 卡片只显示药名/频次/库存，无"今日已服 N/M"状态。用户想确认"今天所有药都吃了吗"只能回今日页逐条看。
- **对照业界**：MyTherapy 药箱列表直接在卡片上显示当日圆点状态。
- **建议**：卡片副标题行追加"今日 1/2"微状态（有排班的药才显示），数据源今日页已有。

### U-7【新增·中】统计页消耗排行进度条在小数值下视觉失真

- **证据**：截图 `20_stats.png`：两种药各消耗"1 片"，进度条双双满格。排行榜条宽未按最大值归一或最小宽度截断逻辑缺失，1 片与 100 片在小样本期视觉无差别。
- **建议**：条宽按同期最大值归一；样本过小时（如各药均 ≤ 若干片）可显示纯数字排行，不出条形。

### U-8【新增·中】日期条固定 ±3 天，回看更早日期必须发现"隐藏月历"

- **证据**：`TodayViewModel.kt:238` `weekDates = (-3L..3L)`，无翻周能力；查看 4 天前须依赖 U-2 所述的徽标隐藏入口或进展页。
- **建议**：日期条支持横向滑动翻周（或首尾加 ‹ › ）；月历入口显性化后此问题自动减轻。

### U-9【新增·低】无深色模式手动开关、无应用锁

- **证据**：`Theme.kt:74` 仅跟随系统；全工程无 Biometric/PIN。FINAL-PRODUCT P1 列过"应用生物识别锁"。
- **说明**：用药数据是敏感健康数据，"纯本地隐私"是卖点，但手机借给家人看一眼的场景里应用锁是最后防线；深色模式对夜间打卡（22:00 时点）的用户体验有直接影响。
- **建议**：深色开关进设置（跟随系统/浅/深三档，成本极低）；应用锁维持 P1 排期但列入 README"明确未做"表，避免定位承诺与实现脱节。

### U-10【新增·低】设置页顶部锚点缺失：权限自检埋放过深

- **证据**：权限自检入口在设置页第 2 分组按钮内（`SettingsScreen.kt:349-355`），而它是"提醒不响"排查的第一入口。用户收到漏提醒反馈时，从今日页到自检页需要 3 跳（见 B-1）。
- **建议**：随 B-1 的健康徽标一并解决；至少把设置页该分组置顶。

### 5.1 功能矩阵（CarroMed vs 主流）

### 5.2 差距解读（哪些该追、哪些不该追）

**不该追（与产品定位冲突，维持明示不做）**：云同步/账号、家人代管推送、药物相互作用数据库、在线问诊——这些与"纯本地零网络"承诺冲突，README 已明示，属合理取舍而非短板。

**结构性短板（建议纳入规划）**：

1. **提醒的"行为闭环"只有半圈**：CarroMed 在"闹钟技术上一定响"上做到了业界最强（三档降级、全量对账、补响窗口），但"响了之后用户不理会怎么办"完全空白——无重复提醒、无漏服升级提醒、无通知常驻。业界经验（Mayo Clinic 试验：升级提醒减少 63% 漏服）表明后半圈对依从率的贡献不小于前半圈。建议把"重复提醒直到确认"从 P1 提到下一个里程碑的第一优先级，且实现上可完全复用现有槽位/闹钟设施。
2. **录入无辅助**：纯手工输入药名。在零网络约束下的折中方案：内置一份**离线常见药模板库**（药名+剂型+单位+常见注意事项标签，几百条即可打包进 APK，无需网络），并在添加页提供模板快捷选择。这是叮咛/吃药啦"扫码"功能的离线替代，直击生僻字痛点。
3. **成果不可展示**：有 420 项测试保证数据真实，但用户拿不出一份能给医生看的东西（B-6）。"记录真实"的价值需要出口。
4. **习惯激励单薄**：有 streak 但断签苛刻（B-3）、0 天负激励（U-2）；MyTherapy 的月历全绿 + 连击卡片的情绪价值已被其用户验证（本机竞品截图：578 连续天数 + "你做得很好!"）——`DoseHistoryCalendarSheet` 底部已有鼓励卡，方向对，力度可以更大。
