## 一、严重度标尺与排序原则

| 级别 | 定义 |
| :-- | :-- |
| **P0** | 核心承诺失效（提醒不响/晚 1 小时）、会写坏数据且难恢复、给用户虚假保证、发布阻断 |
| **P1** | 特定条件下的错误行为或崩溃、跨页面口径矛盾、门禁守不住 |
| **P2** | 边界条件、一致性、性能、可维护性地雷 |
| **P3** | 文案细节、死代码、文档失真 |

排序原则：**提醒主线（到点一定响）→ 数据正确性 → 口径一致 → 测试门禁 → 体验细节 → 卫生**。
同一簇的问题（同一根因或同一文件）合并成一个工单一次修完，避免"修一半"重演（sba 报告的核心观察）。

## 四、对原报告的勘误（核验中发现的定级/表述偏差）

1. **sba P1-5（药箱频次"与引擎语义相反"）→ 降为 M4-4（P2，措辞不一致）**。`每隔 ${n-1} 天` 在中文里就是"每 n 天"，与引擎语义及实体 KDoc 约定一致；真实缺陷仅 `intervalDays <= 1`（每天）被误标"隔天"，以及两页措辞不统一。ds P2-2 的"语义等价但措辞不同"才是准确表述。
2. **sba P2-11（推迟档位不一致）→ 降为 M7-10（P3）**。全局档位读 `app_settings.snooze_minutes`，药品级写 `reminder_settings`，存储独立——"药品级写 25 ⇒ 全局页显示 25"的后果链不成立，仅备份导入 app_settings 才可能出现无选中项。
3. **DB C-16（Dose.of 溢出为负）→ 降为 P3**。Float 路径的 `Math.round(float)` 对超界输入**饱和为 Int.MAX_VALUE**（不变负）；只有 Int 重载在 ≥2,147,484 的极端输入下才负溢出，实害有限。
4. **sba P2-10（"导入 90 后 '+' 永久禁用"）→ 表述修正**。可先减到 55 再加，非永久禁用；取值域不一致本身属实（M7-7）。
5. **DB B-07（主线程 IO）→ 范围扩大**。不止本机 File 路径：Uri 路径的 suspend 函数同样没有 `withContext(Dispatchers.IO)`，两条路径都在 Main 上做文件 IO（M5-4）。
6. **sba P2-13（"迁移实际永远不会执行"）→ 表述修正**。v1 老库升级仍会执行 MIGRATION_1_2 并因同名非 UNIQUE 索引炸 Room schema 校验；当前项目未发布无 v1 用户，风险锁定在发布前（M5-9）。
7. **sba P1-10（错药提醒）→ 定级 P0→P1**。多数情况下 AlarmReceiver 的 `getSlotById == null` 守卫兜住（仅空唤醒）；真实风险限于"恢复更早时点的备份、slot id 空间交叠且该槽位仍 PENDING"的错配路径（M5-1）。
8. **zcg #13 / sbf P1-8（0↔30 哨兵）→ 按设计取舍处理**。代码注释表明 0→30 是有意的档位设计；但"本药固定 30 分钟"不可表达、全局默认变化后显示值说谎的事实成立，仍列 M7-5 待产品拍板。
