**问题**：药品详情页只有一个语义模糊的「✏️ 修改计划」按钮，点进去是"药品信息 + 提醒计划"混合表单；
`precautions`（注意事项）、`unit`（单位）、`alias`（别名）等**药品信息字段根本没有任何编辑入口**；
「提醒设置」这一整层功能**完全不存在**。

**参照 MyTherapy 实机截图**，详情页改为 3 行可点击分节（新增路由 `Screen.ReminderSettings` / `Screen.Inventory`）：

| 分节 | 摘要展示 | 落地页面 |
| :--- | :--- | :--- |
| 💊 药品信息 | 剂型 · 单位 · 默认剂量 / 注意事项条数 / 有效期 | `AddEditMedicationScreen`（`AddEditMode.INFO_ONLY`，**复用添加界面**） |
| ⏰ 提醒设置 | 频次 · 时点 · 疗程 · 重要提醒/推迟/提前 | **新增** `ReminderSettingsScreen` |
| 📦 库存管理 | 剩余量 · 预计可用天数 | **新增** `InventoryScreen` |

- `AddEditMedicationScreen` 支持 `FULL`（新增：三段一次填完，低门槛）/ `INFO_ONLY`（编辑：仅药品信息）；
  标题按模式显示「添加药品」/「编辑药品信息」，不再出现语义错位的「修改计划」。
- 详情页新增：近 30 天依从率、服药历史（可展开 20 条）、库存流水摘要、暂停提醒快捷开关。

### 二、清除 12 个 P0 缺陷（含 2 处会误导健康决策的假数据）

1. **统计报表页 100% 假数据** → 重写为真实聚合。旧代码 `StatsViewModel` 里总剂量 1428 片、依从率 98.2%、
   排行榜药名全是**写死的演示药品**（`medications.size.coerceAtLeast(4)` 强行抬高品种数），
   而用户真实只有 3 条记录。现在周期可切（7/30/365 天），总量、依从率、排行榜全部来自 `dose_records` / `dose_slots` 实际查询。
2. **进展页 7 天打卡矩阵造假** → 旧代码历史 6 天**无条件返回 COMPLETED**、今日只取第一个时点且取不到也默认 COMPLETED。
   现在完全由 `dose_slots` 真实状态分布驱动，六态区分（全部完成/部分/跳过/逾期漏服/未来/未排班）。
3. **编辑药品会清空数据** → 新增 `MedicationDao.updateProfile` 局部 UPDATE。
   旧代码用 `insert(REPLACE)` 整行覆盖，点一次保存就抹掉 `precautions` / `alias` / `noticeShort` / `isPaused` / `isArchived` / `createdAt`。
4. **编辑计划会重置起始日、丢弃疗程** → 新增 `MedicationAdminService.saveReminderPolicy`，
   缺省时沿用历史 `startDate` / `endDate`，`version` 递增（此前每次编辑都把 startDate 设为今天，导致隔日用药相位漂移）。
5. **手动补录"可指定过去时间"是谎言** → 时间字段从只读文本框改为可点选的 `DatePicker` + `TimePicker`，
   附"此刻 / 1 小时前 / 昨天此时"快捷键，并拒绝未来时间。
6. **手动补录"自动扣减库存"开关完全无效** → `logManualDose` 新增 `deductStock` 参数，真正透传。
7. **补药入库的批号/效期被静默丢弃** → `inventory_transactions` 新增两列并落库；去掉假预填的 `2028/05/30`；日期改用日期选择器。
8. **设置页 3 个开关全是装饰** → 新增 `ReminderSettings` 作为唯一消费入口：
   通知栏「推迟 N 分钟」不再是写死的 30 分钟；新增**夜间静音渠道**（Android 渠道重要性不可改，只能靠独立渠道实现），
   「重要提醒」可穿透夜间免打扰。
9. **PRN(按需) 与 CYCLE(周期) 频次引擎支持但 UI 不可达** → 已开放为第 4、5 个分段选项。
10. **跳过/推迟在 App 内零入口**（`TodayViewModel.skipDose` 是死代码）→ 待服卡片**长按**拉起快捷操作面板（推迟 10/15/30/60/120 分、跳过本次）。
11. **数据库仅 `fallbackToDestructiveMigration`** → schema v1→v2 正式迁移（`ADD COLUMN` + 复合索引），
    **移除破坏性降级**：服药历史不可再生，迁移失败必须显式崩溃而非静默清库。
12. **药品名错别字「环抱素」** → 全库与全部文档统一勘误为「环孢素」(Cyclosporine)。

### 三、补齐主流 App 缺失项

- **单位**可选（片/粒/袋/包/支/丸/贴/滴/ml），全库不再写死"片"（此前 8 处 UI 硬编码）。
- **服药与用餐关系**枚举（空腹/饭前/随餐/餐后/睡前 + 服药时段），一键铺排时按时段自动推断标签。
- **疗程三选项**（长期无限期 / 截止到某日 / 共 N 天），绝不强制填结束日期（用药提醒管家的 365 天上限是明确反面教材）。

- **注意事项** 12 个常用标签多选 + 自定义输入。
- **重要提醒 / 提前提醒 / 按药品推迟时长**（此前只能在全局设置，且根本没生效）。
- **库存盘点校准**、**库存追踪开关**、**药品有效期与临期提醒**（`CALIBRATION_ADJUST` 此前无任何 UI 入口）。
- **药箱搜索与排序**（默认/名称/库存由少到多/临期优先）。
- **库存流水 CSV 导出**（此前只有服药明细 CSV）。
- 新增 DAO 聚合查询（`GROUP BY medication_id, scheduled_date, status`），统计与矩阵共用同一数据源走索引。

### 四、UI/UX 与状态诚实性

- **首启空态区分**：「药箱还是空的 + 添加第一个药品」引导卡 vs「这一天没有待服任务」——旧版全新用户和"恰好没排班"显示同一句话。
