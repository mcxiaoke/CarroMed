### A1a 库存余额改为派生（本次最大的一步）

- **删除 `medications.current_stock` 列。** 余额的唯一权威定义改为
  `SUM(inventory_transactions.change_amount)`，由 `MedicationOverview`（LEFT JOIN 聚合子查询）
  提供给读路径。
- 6 条库存写路径中 **5 条退化为单条 INSERT**（append-only），不再有 read-modify-write，
  并发打卡不再可能丢失更新。仅「盘点校准」「开启追踪」需要读余额（本质要求算差额）。
- **`coerceAtLeast(0f)` 全部移除** —— 那正是库存守恒被打破的根因。
  负库存现在被正式支持（`FINAL-PRODUCT` D-9），且在今日页/药箱页/详情页/补录页
  有专门的"待盘点"文案与配色，与"快没药了"区分开。
- 打卡 / 跳过 / 撤销的**幂等锚点下沉到 SQL**（`markCompletedIfOpen` / `markSkippedIfOpen` /
  `revertToPending` 返回受影响行数），取代"先查后写"的竞态窗口。
- **撤销不再物理删除服药事实**，改为标记 `RecordStatus.REVERTED`；
  `DoseRecordDao` 删掉全部按 id / slot 的删除方法（`deleteAllRecords` 仅留给整库恢复）。
- `RecordStatus.RETROSPECTIVE` 枚举值删除。原先"是否补录"与"依从分类"挤在一个枚举里，
  导致所有聚合 SQL 写死 `status='COMPLETED'` —— **补录超过 2 分钟的服药，库存照扣、统计不计**。
  现改为 `isRetrospective` 布尔列，统计口径无需任何特判。
- 补药入库复用领域层 `DoseTrackingService.refillStock`，删除 ViewModel 里重复实现的内联事务。
- 库存页的写命令从 19 列的 `updateProfile` 拆成 `updateExpiryDate` + `updateMinStockAlert`
  两条细粒度命令（原本被迫重传全部档案字段，内含 read-modify-write 竞态）。
- 删除死文件 `core/data/SampleDataSeeder.kt`（0 调用点，与 debug 版重复，
  且带着药品名错别字「环抱素」混进 release 包）。

### A1b 整数毫单位（D-7）

- 6 个金额列从 `REAL` 改为整数毫单位（1 片 = 1000）：
  `change_amount` / `balance_after` / `dose_taken` / `dose_amount` / `default_dose` / `min_stock_alert`。
  浮点加法不满足结合律，长期累加必然漂移，而余额恰是累加得来的。
- 新增值对象 `core.domain.model.Dose`（`@JvmInline value class`）：实体层用 `Int`，
  领域/UI 层用 `Dose`，转换只发生在两个边界。
- 统计页**跨单位不再求和**（P0-7）：按单位分组，只有全部同单位时才给总量大数字，
  否则逐单位并列。宁可不给数字，也不能给错数字。
- 统计消耗排名的 `mapIndexedNotNull` 索引错位修复（原会导致"第 1 名已归档时
  UI 从『2.』开始显示"）。
- 全库数量格式化统一到 `ui.component.Quantity`（此前有四套并存写法，
  同一数值在四个页面显示成四种样子）。
- 备份 JSON 字段加 `Milli` 后缀明示口径。

### 顺带修掉的产品缺陷

- `InventoryViewModel` 的频次文案此前拿 `times.size`（时点个数）当"间隔天数"渲染，
  与同页用真实 `intervalDays` 算的"预计可用天数"自相矛盾。
- 周期用药的日均消耗此前写死按 5 天/周折算，对"吃 2 停 6"会把消耗高估 20 倍。
- 编辑药品不再预填库存余额（编辑账面在语义上等于直接改账面），且不再用默认值 "10"
  污染 `minStockAlert`（0 的语义是"关闭告警"）。
- 今日页/库存页/详情页的低库存判定此前**不传** `minStockAlert`，
  引擎只剩"7 天内"一条硬规则，与用户配置的预警线不一致。

### 本轮自己引入又抓回来的 4 个 bug（记录在此以示门禁有效）

1. **App 崩溃**：`TodayScreen` 的 `LazyColumn` 里低库存告警用药品 id、待服/已服用槽位 id
   作 key，两条独立自增序列首条都是 1 → 滚动到冲突项时
   `IllegalArgumentException: Key "1" was already used`。**只在滚动时崩，第一屏看起来完全正常。**
2. **量纲错误**：`CabinetScreen` / `TodayScreen` 直接拿实体的 `minStockAlert`（毫单位 Int）
   与展示值 Float 比较 → `50f <= 15000` 恒真 → **4 个药全部误报低库存**。
   Kotlin 允许 `Float <= Int`，编译器抓不到，靠类型设计（`MedicationOverview` 只暴露 Float）挡住。
3. **量纲错误**：`InventoryViewModel.dosesPerScheduledDay` 漏了毫单位换算 →
   日均消耗显示 1000.00、预计可用天数算成 0。
4. `AppDatabase` 加了 `fallbackToDestructiveMigration()`，让 schema 变更在开发期能落地。
   **发布前必须删掉这一行**（代码里有 `TODO`）。
