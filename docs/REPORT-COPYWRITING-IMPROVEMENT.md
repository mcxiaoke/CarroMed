# CarroMed 文案系统性梳理与优化建议报告

> 日期：2026-10-18  
> 目标：提升用药交互的温度感与准确性，消除误导性/歧义用词，统一全站核心术语。

---

## 一、全屏提醒操作用词专项评估（「忽略」vs「关闭」）

### 1.1 业务背景与用户心智
闹钟到点触发全屏 Activity 时，用户可能正处于会议、驾驶、洗浴等场景，或者药品不在身旁。此时用户的真实心理是：
**“我现在没法吃，但我之后还要吃，请先把这个全屏遮挡关掉，不要影响我用手机，待会儿提醒我或等我忙完去 App 里补。”**

### 1.2 候选用词对比与客观评估

| 用词选项 | 语义属性 | 潜在心理负担 / 用户困惑 | 推荐等级 |
| :--- | :--- | :--- | :--- |
| **跳过本次**（旧版） | 处方决策动作 | **致命误触**：用户以为是暂时跳出，结果直接判定放弃本剂且不可逆。 | ❌ 严禁使用 |
| **忽略** | 消极中性词 | **负罪感与不确定**：在系统通知/安全警告语境中常代表“置之不理/放弃”；用户会困惑“我点了忽略，今天是不是就算跳过了？还会不会响？” | ⚠️ 存在歧义 |
| **关闭**（用户建议） | **纯物理动作** | **零心理负担**：中性、直接（Close/Dismiss）。表达“关掉当前浮层界面”，没有任何篡改服药事实的暗示，完美契合“移开界面、暂不表态”的行为。 | ⭐⭐⭐⭐⭐ **首选推荐** |
| **稍后处理** | 状态动词 | **与上方冲突**：全屏中央已有「稍后再提醒（30/60/90分钟）」区域，底部再放“稍后”容易产生双重“稍后”认知混乱。 | ⚠️ 区域认知冲突 |
| **暂不处理** | 状态描述 | 略显冗长且更偏被动，不如动词“关闭”干脆明了。 | ⭐⭐⭐ 备选 |

**评估结论**：
将原先的「跳过本次」改为**「关闭」**是最优解。它既不带任何主观判断，也不会给用户造成“是不是放弃吃药了”的心理压力。

## 二、全应用文案系统性梳理

对 `app/src/main/res/values/strings*.xml` 的全部文案进行实证核对，归纳出以下 4 类典型问题并给出优化方案：

### 1. 消除冷冰冰的“系统/工业化术语”

用药管理软件面向的是患者及家属（尤其是中老年患者），冷冰冰的进销存或技术词汇容易带来距离感。

| 当前文案 / 涉及文件 | 当前存在的问题 | 推荐方案 | 优化收益 |
| :--- | :--- | :--- | :--- |
| `set_repeat_reminder_title`<br>（`strings_set.xml`）<br>**「忽略后重复提醒」** | “忽略”带有责备/轻视感，且与用户的实际场景不符（用户并未想忽略，只是未确认或关掉了通知）。 | **「未确认时重复提醒」**<br>描述改为：提醒弹出后若未确认服药，按设定间隔再次提醒。 | 语义严谨准确，更具服务感。 |
| `rdetail_stock_overspent`<br>（`strings_rdetail.xml`）<br>**「账面 %1$s %2$s（待盘点）」** | “账面”、“盘点”是财务与仓储术语，过于冷硬。 | **「记录余量 %1$s %2$s（待校准）」** | 与库存管理页的“校准”概念统一。 |
| `today_pending_hint_future`<br>（`strings_today.xml`）<br>**「未来用药预览 · 到达当天方可记录」** | 略带机械性规章语气。 | **「未来用药计划 · 到达当天即可确认」** | 从限制语气（方可）变为服务引导（即可）。 |
| `set_permission_check_desc`<br>（`strings_set.xml`）<br>**「排查精确闹钟、系统白名单与自启权限，确保灭屏休眠零漏报。」** | “灭屏休眠零漏报”偏工程术语。 | **「排查精确闹钟与后台运行权限，确保手机息屏时准时提醒。」** | 通俗直白，老人也能读懂。 |

### 2. 统一核心高频词汇体系

当前工程中存在同一概念在不同页面用词各异的情况：

| 业务概念 | 当前混用的不同表述 | 推荐标准体系 | 统一说明 |
| :--- | :--- | :--- | :--- |
| **服药动作** | • 确认已服 (`alert_action_take`)<br>• 确认服药 (`today_cd_confirm_dose`)<br>• 确认服用 (`rdetail_confirm`)<br>• 记录服药 (`today_manual_log`)<br>• 打卡 (`set_completion_sound_desc`) | **操作按钮**：统一为「确认服药」或已响铃通知上的「确认已服」<br>**功能入口**：统一为「记录用药」<br>**弱化术语**：在所有提示中删除「打卡」，改称「服药记录」 | “打卡”属于考勤术语，家庭用药场景称“服药记录”或“确认服药”更显关怀。 |
| **药品存量** | • 库存 (`inv_title`)<br>• 余量 (`inv_current_stock`)<br>• 余药 (`inv_refill`)<br>• 账面 (`rdetail_stock_overspent`) | **页面模块**：称「余药与库存」或「库存管理」<br>**具体数值**：统一称为「药品余量」或「剩余」<br>**动作**：补充余药（入库）/ 校准实际数量 | 日常生活中老人通常说“这盒药还剩多少粒”，用“余量”比单纯的“库存”更有亲和力。 |
| **超时/未服** | • 已逾期 (`rdetail_status_expired`)<br>• 漏服 (`today_calendar_legend_missed`)<br>• 已过服药时间待确认 (`today_expired_unconfirmed`) | **当天尚未结束时**：统一称「已过时间（待确认）」或「超时未服」<br>**跨日已结算后**：统一称「未服」或「漏服」 | 当天时间刚过 1 小时就标注“已逾期/漏服”会引发不必要的焦虑，当天应强化“待确认”。 |
| **推迟/延后** | • 默认推迟时长 (`set_snooze_title`)<br>• 稍后再提醒 (`alert_snooze_section`)<br>• 稍后提醒 (`rdetail_snooze_label`)<br>• 推迟 %1$d 分钟 (`notif_action_snooze`) | **全局与卡片说明**：统一为「稍后提醒」<br>**具体时长选项**：统一样式为「%1$d 分钟」或「稍后 %1$d 分钟」 | “推迟”略显被动，“稍后提醒”是从用户的利益出发提供关照。 |

### 3. 优化容易引起患者心理负担的警告文案

| 位置 | 原文案 | 改进推荐 | 优化 rationale |
| :--- | :--- | :--- | :--- |
| `strings_inv.xml` (效期警告) | `昨天已过期，请勿继续服用`<br>`已过期 %1$d 天，请勿继续服用` | `已过保质期（已过期 %1$d 天），建议更换新药并遵医嘱` | 在用药安全的前提下，语气更为专业克制，提示遵医嘱处置。 |
| `strings_today.xml` (未服提示) | `已过服药时间（%1$s %2$s），待确认` | `已过计划时间 · 待确认服药` | 格式更简洁利落，降低紧迫压迫感。 |
| `strings_notif.xml` (夜间提示) | `\n夜间静音中（可在设置中调整，或将该药设为重要提醒）` | `\n已开启夜间免打扰（重要药品可单独开启强提醒）` | 强调“保护夜间睡眠”的同时告知解决方案。 |

## 三、推荐落地的第一批文案调整清单

若认可上述梳理方案，建议优先按以下清单分步调整：

1. **全屏提醒页**：
   - 将 `R.string.alert_action_ignore` 的文案从「忽略」正式调整为**「关闭」**（对应 `alert_action_close`）。
2. **全局设置页**：
   - 将 `set_repeat_reminder_title` 从「忽略后重复提醒」调整为**「未确认时重复提醒」**。
   - 描述调整为：“提醒发出后若未确认服药，按设定间隔再次提醒”。
3. **记录详情页**：
   - 将 `rdetail_stock_overspent` 从「账面 %1$s %2$s（待盘点）」调整为**「记录余量 %1$s %2$s（待校准）」**。
   - 将操作文案中的“打卡”彻底清理，统一为“服药”与“确认”。
