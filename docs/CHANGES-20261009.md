# 变更记录 - 2026-10-09

### 2026-10-09 21:38:12
- **修复切回前台时列表被强制换日引发的"首页乱跳"（最小改法）**：
  1. **定位**：`TodayViewModel.onResume()` 的跨天判据为 `lastResumeDate != realToday || current > realToday`。用户翻到未来日（明天/后天预览排班）时 `current > realToday` **恒为真**，于**每一次**回到前台（从别的 App、系统日期选择器、厂商设置页、全屏提醒页返回）都会把 `selectedDate` 强行改回今天 ⇒ 整页列表整体替换，表现为"首页乱跳"、手指落点下的卡片已不是原来那条。日志实证 3 处（20:48:40 / 20:55:14 等）。
  2. **改法**：判据只保留系统事实 `lastResumeDate != realToday`（真实日期是否翻面），删除 `current > realToday` 这一支；`current` 的读取移入分支内。**行为差异仅 1 行**，`init` 里那条克制的跨天推进器未改动。
  3. **回归测试**：新增 `TodayViewModel 同一天内预览未来排班再 onResume 不会被弹回今天`。该测试刻意**不在 `onResume()` 后立刻读 `uiState.value`** —— 主状态流里按日期的槽位查询是异步冷流，立刻读到的永远是旧值，会导致"假绿"；改为留 1.5s 观察窗等状态流自行重算。已用"临时改回旧判据"实测该测试会失败（`selectedDate=2026-10-07`），确认真能守住该不变量。
  4. **全量验证**：`testDebugUnitTest` 609 项全通过（原 608 + 新增 1）；`assembleDebug` / `assembleRelease` 编译通过。
  5. **备注（非本次范围）**：本次"自动确认/自动跳过"的真凶是设备上的无障碍自动点击类应用（GKD）。应用侧只有上述"乱跳"这一条缺陷；`MainActivity` 的 `singleTask` + `NavController` 状态恢复导致"冷启动落在上次的二级页"、列表缺 `animateItem()`、今日页「跳过」缺同级撤销入口，均记录在 `docs/DIAGNOSIS-AUTO-CLICK-LAYOUT-JUMP-20261009.md`，另轮处理。

### 2026-10-09 13:10:57
- **彻底根除 jqwik 扫描 NPE，移除 Test 任务中的通配排除 `exclude("**/*$*")`**：
  1. **定位根因**：Kotlin 2.2 编译器在 lambda 闭包内遇到 `when(enum)` 会生成局部匿名合成类（`$1$WhenMappings`），其 `Class.getCanonicalName()` 在 JVM 反射中返回 `null`，导致 jqwik 引擎扫描无判空保护而抛出 NPE。
  2. **根治方案**：重构 `StatsDaoAggregationTest.kt`，将闭包内的 `when` 映射提取为类私有方法 `breakdownOf`，彻底杜绝局部匿名合成类的生成。
  3. **移除 exclude**：已从 `app/build.gradle.kts` 中完全删除 `exclude("**/*$*")`，保留 Gradle 默认的干净任务配置，避免影响 JUnit 5 `@Nested` 等嵌套测试类的发现。
  4. **全量验证**：`testDebugUnitTest`（608 项）和 `verifyRoborazziDebug` 均 100% 通过。
