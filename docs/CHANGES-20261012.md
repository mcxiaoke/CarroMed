# 2026-10-12 变更记录

## 界面全屏刷新 / 闪烁问题整改

排查与方案见 [UI-RECOMPOSITION-AUDIT-20261012.md](UI-RECOMPOSITION-AUDIT-20261012.md)。

### 根因（先排除误判）

全项目搜索 `isLoading = true` **只有 1 处**（`TodayViewModel.kt:244`，仅重试路径）。
所有 `load()` 都不会把 `isLoading` 置回 true，因此**「转圈 ↔ 内容」来回闪在结构上不存在**。

真正根因：14 个 Screen 全部用
`val uiState by vm.uiState.collectAsStateWithLifecycle()`
把整个 state 收进一个局部变量。Compose 的 snapshot 跟踪粒度是「读的是哪个
`State` 对象」而非「读了哪个字段」，因此**任一字段变化 ⇒ 整页重组**。

### 已实施（第 1 批）

| 提交 | 内容 |
| :--- | :--- |
| `316fde9` | `imePadding` 从 `LazyColumn` 移到外层 `Box`（6 个表单页） |
| `0eb354c` | `SimpleDateFormat`/`DateTimeFormatter` 提为文件顶层；删除失效的 `remember(uiState)`；去掉输入框双重过滤 |

- **`imePadding` 挂在 `LazyColumn` 上**是「闪烁」最直接的来源：键盘每弹出一个
  字符的高度变化都让**整个列表**重新测量+布局，于是「敲一个数字」被放大成
  「全屏内容上下跳一下」。
- **`InventoryScreen.kt:91` 的 `remember(uiState)`** 是两个错误叠加：key 是整个
  17 字段 data class；而 `viewModel.isDirty()` 内部读 `_uiState.value`——
  **StateFlow 的值不是 snapshot state**，Compose 根本追踪不到，这个缓存
  **从不产生跳过效果**，纯负担。改为直接调用。
- **输入框双重过滤**：Screen 层滤一遍（只认 `isDigit`/`.`），VM 内部
  `DecimalInput.filter` 又滤一遍（**额外接受全角 `。`/`．`**）。两层规则不一致，
  全角小数点被静默吞掉。统一走 `DecimalInput.filter`。

- **全局探针跨页误唤醒**：`observeDecidedSlotCount()` / `observeRecordCount()`
  的 SQL **没有 `medication_id` 过滤**（`DoseSlotDao.kt:484-493`、
  `DoseRecordDao.kt:141-149`），是全库计数，却被库存页/详情页当作本页探针。
  给**任意一味药**打卡 ⇒ 本页数据一字节没变却重跑 4~8 条查询
  （详情页其中一条还是 `ensureDefaults` **写操作**）。新增
  `observeDecidedSlotCountForMedication`，参照既有的
  `observeRecordCountForMedication`。**统计页保持全库探针**——它本来就聚合全库。

- **药箱每敲一字跑 2 条 DB 查询**：`_keyword` 是 `combine` 的源之一，而 transform
  里有 `getAllActivePolicies()` + `getTimesForPolicies()`。搜索是纯内存过滤，
  本就不该碰数据库。现改为在该链**之后**合并关键词。

- **提醒页每键两轮全屏重组**：`mutate()` 无条件调 `refreshPreview()`，而后者
  末尾又有一次 `_uiState.value = ...` ⇒ 任何一次表单改动都是**两次 StateFlow 发射**。
  剂量框也走 `mutate`，但剂量**不影响哪几天排班**（预览只有时刻+标签）。
  加 `refreshPreview` 开关按调用点下放；`updateTime` 按**本次实际改了哪些字段**决定。

   `AddEditMedicationScreen.kt:430-438`、`CabinetScreen.kt:102-105`）。
