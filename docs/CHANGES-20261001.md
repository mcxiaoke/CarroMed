## P0 修复（4 条）

1. **备份恢复在大数据量下必然失败（orsbf P0-1）**
   - 恢复回填全部改为 `chunked(50)` 分批插入（`DataExporter.RESTORE_CHUNK_SIZE`）：
     Room 的 `@Insert(List)` 是一条多值 INSERT，Android（minSdk 26 档）SQLite 变量上限 999，
     槽位 11 列/行 ≈ 90 行封顶，整表插入必然 `bind or column index out of range` 并整体回滚。
   - `DoseTrackingService.reconcileSchedule` 的 `insertAll` / `deleteByIds` 同步分批（该方法幂等可重入）。
   - 全部调用点仍在 `withTransaction` 内，原子性不变。

2. **剂量量化不守正（orsbf P0-4）**
   - `saveReminderPolicy` 改为校验**量化后**的毫单位：`Dose.of(dose).milli <= 0` 拒绝
     （`0.0004f` 静默归零 ⇒ 打卡照记库存永不扣；超大值溢出 Int 为负 ⇒ 打卡反而**加**库存）。
   - `takeDose` 的 `takenAmount` 分支、`logManualDose` 补上同一道量化后守卫；
     `slot.doseAmount` 分支不重复拒绝，避免旧备份存量数据变成"无法打卡"。

3. **恢复后闹钟被拆掉不重建（orsbf P1-1）**
   - `importBackup` 的成功与失败两条路径都补 `AlarmReconciler.rescheduleAll`（runCatching 包裹 + ERROR 日志）。
   - 旧行为：恢复失败只回滚数据库，闹钟已被 `cancelAllAlarmsBeforeRestore` 拆掉，
     要等到用户下次打开 App / 周期对账才有提醒。

4. **通知不可达时补响风暴（orsbf P0-5，止血版）**
   - `showDoseNotification` 返回 `Boolean`：前置 `areNotificationsEnabled()` + 渠道 `IMPORTANCE_NONE` 检查，
     不可达直接跳过并落 ERROR 日志（旧实现静默空操作却记"notification shown"假阳性）。
   - `AlarmReceiver` 按真实投递结果记日志；不可达时**不入队续期对账**——
     旧链路里"托盘里没有通知"恒为 false，每条漏药以 30 秒为周期唤醒设备直到 2 小时窗口结束。
   - `AlarmReconciler` 两条补响分支加 `areNotificationsReachable` 前置（新增 `Notifications` 辅助函数）。

## P1 修复（9 条）

5. **RUNWAY 哨兵撞码（orsbf P1-4）**：`RUNWAY_UNLIMITED` 从 `-1` 改为 `Int.MIN_VALUE`
   （库存 -1、日消耗 1 时旧哨兵被精确撞上，"已超支"渲染成"—"且低库存横幅不触发）。
   库存页与详情页对负天数新增「已超支」分支（新字符串 `inv_runway_overspent` /
   `mdetail_sum_runway_overspent`）；`MedicationDetailViewModel` 初值从 `Int.MAX_VALUE` 改为哨兵。
6. **长周期 INTERVAL 日消耗高估 4.3 倍（orsbf P1-5）**：新增
   `StatsEngine.scheduledDaysPerWeekExact(): Double`（`7.0/n` 不取整），
   `calculateStockRunwayBySchedule` 改收 Double，两个 ViewModel 同步切换。
   取整版保留（展示语义 + 下界 1 防御仍在）。
7. **进展页触底加载永不触发（orsbf P2-12）**：`LaunchedEffect` key 补上 `hasMoreTimeline`
   —— 它是普通捕获值，首次为 false 时闭包被捕获，翻页一次都不会发生。
8. **keyset 分页同毫秒簇丢记录（orsbf P1-3）**：`getRecordsBefore` 改复合游标
   `(actual_ts, id)`，`observeLatestRecords` 排序同口径补 `id DESC`；
   `ProgressViewModel` 游标取簇内最小 id，合并排序显式 `(ts, id)` 双键。
   KDoc 修正：旧文把"严格小于"论证成正确性要求——它恰恰是丢数据的根因。
9. **时点串 trim 口径分裂（orsbf P2-7）**：`saveReminderPolicy` 写库前 `timeOfDay = t.time.trim()`
   （" 21:00 " 此前能通过校验、投影解析失败回退 08:00）。
10. **startDate/endDate 无格式防线（orsbf P2-8）**：入口 require ISO 可解析 + `end >= start`，
    挡住"疗程边界消失、提醒永不停"与"过去排班复活"两类投影 fail-open。
11. **Locale 写入持久化串（orsbf P1-18）**：写 `policy_times.time_of_day` /
    `dose_slots.scheduled_date` 的 5 处 `String.format` 全部 `Locale.ROOT`
    （`ar-EG` 等 locale 下 `%02d` 产出非 ASCII 数字，投影解析即失败）。
12. **撤销后重排失败被静默吞掉（orsbf P1-7）**：`DoseEntryActions.undo` 的 `rescheduleAll`
    失败改为 ERROR 日志 + `ReconcileWorker.enqueueOneShot` 退避重试兜底
    （不向调用方抛：撤销本体已落库，抛错会让用户重试一个已完成的动作）。
13. **补药页渠道预填商业机构名（orsbf P2-6）**：`RefillViewModel.channel` 默认 `""` +
    placeholder「未填写」——机构名此前会被不经确认地写进流水、CSV 与备份。
