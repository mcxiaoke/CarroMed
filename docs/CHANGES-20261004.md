**① 解耦：`logManualDose` 不再按时间认领/结清槽位**

- `DoseTrackingService.logManualDose` 删掉"同日开放槽位按时间最近自动结清"整段逻辑
  （2026-10-01 引入的启发式，见 `DoseTrackingServiceTest` 原「自动结清并关联槽位」用例），
  产出的服药事实 `slot_id` **恒为 null**；同步删除 `MANUAL_DOSE_MATCH_WINDOW_MS`（上一轮加的 ±3h 窗口）。
- 理由（写进 KDoc）：拿**时间**代理**用户意图**，两个方向都静默出错 ——
  该绑没绑→槽位仍开放、闹钟可能再响、再确认即二次扣库存；不该绑却绑了→12:00 的额外加服
  被记成"20:00 那次已服"，**该响的不响**。且那次绑定对用户**完全不可见**。
- 该用例改写为「单次服用与计划完全独立 不结清也不关联任何槽位」，直接断言槽位仍是 `PENDING`、
  `actual_taken_ts` 仍为 null、事实 `slotId` 为 null。

  否则今日清单（读 `slot.actualTakenTs`）与记录详情（读 `record.actualTs`）会对同一次服药各说一套。
