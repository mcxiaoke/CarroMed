## 一、 背景与梳理目标

### 1.1 现状与背景
在 2026-09-30 完成的「中英双语与硬编码抽取（B1–B6）」批次中，CarroMed 将原先分散在 Compose 界面、ViewModel、Domain 模型与通知层中的 750+ 处硬编码字符串统一归拢到了 `res/values/strings_*.xml` 资源文件中。

由于此前抽取的首要目标是**“把硬编码中文字符串先抽取干净、理顺数据与枚举结构”**，大部分文案仍保留了开发初期的原始文本。经过深入盘点，现有文案存在大量**开发者视角自白、极客/审计专业术语外露、动作动词混乱、情绪化标点与说教感强、甚至存在严重医学语义歧义**的问题。

### 1.2 梳理目标
参考 **Apple Health（苹果健康用药模块）**、**Medisafe（全球顶级用药管理）**、**MyTherapy** 以及主流提醒与健康类 Top 榜应用的最佳实践：
1. **统一专业术语与动词体系**：彻底理清“服药 vs 吃药”、“记录服药 vs 打卡”、“修改状态 vs 改判”；
2. **剔除技术与会计进销存黑话**：消除“冲正”、“台账”、“流水账”、“悬空引用”、“落库”等开发与会计词汇，回归普通用户易懂的健康生活语言；
3. **消除严重歧义与误导**：彻底纠正依从率统计中分母写成“已到期”引发的“药品变质过期”误解，纠正“这味药”等不规范量词；
4. **精简冗长说教，提升界面呼吸感**：去掉按钮上的说明括号（如“确认入库 (生成流水账)”），去掉向用户解释产品架构（如“三者分开管理”）的碎碎念；
5. **规范标点与排版**：统一中英文混排空格、全半角标点，清理冗余 Emoji，确保界面严谨、温和、克制、可靠。

## 二、 业界顶级标杆对比与设计原则

### 2.1 顶级标杆实践分析

| 产品 | 核心设计哲学 | 动词规范 | 记录与计划 | 余量/库存 |
| :--- | :--- | :--- | :--- | :--- |
| **Apple Health (苹果健康)** | 极度克制、尊重隐私、医疗规范、无说教感 | 「记录为服用」「跳过」「编辑」 | 「今天」「已记录」「计划」 | 「剩余剂量」「余量预警」「添加余量」 |
| **Medisafe** | 友好亲和、清晰行动导向、强化依从 | 「服用」「推迟」「跳过」 | 「今日清单」「用药历史」「应服」 | 「药品余量」「补充余药」「低余量提醒」 |
| **MyTherapy** | 严谨可靠、陪伴感、直观明了 | 「确认」「推迟」「标记」 | 「今日任务」「服药概览」「日历」 | 「药箱」「补充用药」 |

### 2.2 本次优化的五项文案铁律

1. **医疗健康规范（Medical & Healthy）**：
   - 动作一律用「服药 / 服用 / 记录服药」，禁用口语化「吃药」或社畜打卡用语「打卡」；
   - 药品量词规范使用「种 / 该药品」，西药禁称「这味药」。
2. **用户视角优先，杜绝技术黑话（Human-Centered）**：
   - 绝不向用户呈现任何数据库、架构设计或财务会计概念（禁止出现：冲正、台账、落库、悬空引用、三者分开管理、整库快照）。
3. **零歧义与科学严谨（Zero Ambiguity）**：
   - 药品应用中，“到期/过期”具有强烈的“药品失效/变质”心智。统计指标分母严禁使用“已到期”，统一为「计划服药」或「应服次数」。
4. **克制简练，释放界面呼吸感（Frictionless & Clean）**：
   - 操作按钮主文案保持 2–4 字纯粹动词（如「确认添加」、「跳过本次」），禁止在按钮文本内带括号解释（如「确认入库 (生成流水账)」）；
   - 清理说明文字中不必要的 PRD 心理活动与开发者自白。
5. **工业级中文排版规范（Typography Discipline）**：
   - 中文与西文/数字之间留有一空格（如 `近 7 天`、`1 片`、`08:00`）；
   - 全角半角符号统一，句末无特殊警示不乱加感叹号。

## 三、 七大核心问题深度剖析

### 痛点 1：动词体系分裂与轻佻用词（“吃” vs “服” vs “打卡”）
* **现状表现**：
  * 通知栏写「✅ 确认已吃」、「该吃药了」；
  * 今日清单写「待服药」、「今日已服」、「未来提醒预览 · 到达当天才能打卡」；
  * 进度页写「7 天打卡矩阵」、「近 7 天的真实打卡情况」；
  * 补录页写「忘记打卡或未带手机？」。
* **问题实质**：
  * “吃”过于口语化，且无法覆盖外用药、滴剂、喷雾剂等剂型；
  * “打卡”属于考勤打卡或社交习惯签到，对于需要遵医嘱的治病/慢病管理软件而言显得轻浮、缺乏责任感。
* **标准化方案**：
  * 动作统一收敛为**「服药」**或**「服用」**（如「确认服药」、「已服」）；
  * 行为记录收敛为**「记录服药」**或**「记录」**（如「记录服药」、「未记录」）。

### 痛点 2：把用户当会计与程序员的“黑话”外露
* **现状表现**：
  * `note_ledger_undo_revert`: "用户误触打卡撤销冲正"
  * `today_stock_overspent`: "%1$s 账面 %2$s %3$s，已超出记录库存，请盘点校准"
  * `inv_calibrate_description`: "换了包装、之前漏记或首次建档时，把账面修正为实物真实数量。系统会写入一条盘点流水，保证账实可追溯。"
  * `inv_ledger_balance_rule`: "账面 = 全部流水变动之和，恒等于当前余量"
  * `refill_confirm_button`: "确认入库 (生成流水账)"
  * `rdetail_dose_edit_hint`: "改剂量会自动补一条差额流水，库存台账保持对得上。"
  * `rdetail_footnote_reverted`: "...库存台账也不会出现悬空引用。"
  * `rdetail_note_future_hint`: "...现在填写的内容不会落库。"
* **问题实质**：
  * “冲正”是银行核心电算化和复式记账术语；“账面”、“台账”、“流水账”是进销存仓管概念；“落库”、“悬空引用”是数据库与 C++ 内存指针概念。
  * 普通患者或家属打开 App，只想知道“药还剩多少”、“记错了怎么撤销”，满屏的会计与编程术语造成认知负担。
* **标准化方案**：
  * “冲正” ➔ 改为 **「撤销恢复」** 或 **「撤销返还余量」**；
  * “账面 / 台账” ➔ 改为 **「记录余量」** 或 **「当前余量」**；
  * “盘点校准” ➔ 改为 **「校准库存」** 或 **「修正余量」**；
  * “采购入库 / 补药入库” ➔ 改为 **「添加库存」** 或 **「补充余药」**；
  * 彻底删除“悬空引用”、“不会落库”、“生成流水账”等开发者喃喃自语。

### 痛点 3：致命歧义——把计划次数写成“已到期”
* **现状表现**：
  * `mdetail_adherence_summary`: "按时服药 %1$d 次 / 已到期 %2$d 次"
  * `prog_overall_adherence_detail`: "按时服药 %1$d 次 / 已到期 %2$d 次"
  * `prog_overall_no_due`: "近 7 天还没有到期的服药任务"
  * `prog_no_due_short`: "暂无到期"
* **问题实质**：
  * 用户看到“已到期 15 次”，第一反应必然是“天哪，我的药过期了 15 次吗？这药还能不能吃？！”
  * 这是直接把英文 `due` / `dueTasks` 生硬翻译为“到期”造成的恶劣歧义。
* **标准化方案**：
  * 在依从率（实际服用 / 应服）中，分母统一规范为**「计划 %2$d 次」**或**「应服 %2$d 次」**；
  * “暂无到期任务”改为 **「暂无待服任务」** 或 **「暂无计划任务」**。

### 痛点 4：把状态机转换当法庭审判的“改判”
* **现状表现**：
  * `today_completed_hint`: "点开可撤销或改判"
  * `rdetail_confirm_rejudged`: "确认服用（改判）"
  * `rdetail_skip_rejudged`: "跳过（改判）"
  * `note_record_rejudge_taken`: "改判为已服"
  * `rdetail_footnote_completed_no_undo`: "...只能在「跳过」与「确认」之间改判。"
* **问题实质**：
  * “改判”带有强烈的司法审判和违规纠错色彩，用户只是误点了“跳过”想改回“已服”，给用户扣上“改判”的大帽子，体验极差。
* **标准化方案**：
  * 统一使用**「修改状态」**、**「更改为已服」**、**「更改为跳过」**。

### 痛点 5：产品碎碎念、说教感与解释架构
* **现状表现**：
  * `cabinet_hint_text`: "点击药品进入详情页，药品信息 / 提醒设置 / 库存管理三者分开管理"（向用户背诵软件工程的分层设计）
  * `man_backfill_window`: "补录最常用于「忘记打卡」场景，因此必须能指定过去时刻；只能补录最近 %1$d 天内的服药。"（把 PRD 论证逻辑写在用户界面）
  * `set_local_restore_desc`: "直接选用 App 刚生成的备份（系统文件选择器看不到这个目录）"（向用户吐槽 Android 系统机制）
  * `perm_exact_alarm_desc`: "决定提醒是「到点必响」还是「系统择机送达」。用药提醒属于《Android 闹钟类应用》标准场景，CarroMed 已声明 USE_EXACT_ALARM，正常安装即自动授予；若这里显示未授权，说明系统把它降级处理了。"（把开发者写给 Google Play 的权限申诉信放出来）
* **标准化方案**：
  * 砍掉一切自说自话，提炼为精练、友好、对用户直接有用的指引。

### 痛点 6：不标准量词与选项代码残留
* **现状表现**：
  * `mdetail_sum_no_plan`: "尚未设置提醒 · 这味药不会自动提醒 → 点击设置"（西药、维生素不称“味”）
  * `rem_type_interval`: "隔 N 天"（单选框标题残留伪代码占位符 N）
  * `nav_tab_progress`: "进展"（作为四大核心 Tab，含义模糊，不知所云）
  * `stats_title`: "统计报表"（手机个人 App 偏向沉重）
  * `perm_title`: "系统特权自检与保活指引"（“特权”一词让人产生对系统提权/恶意软件的疑虑）
* **标准化方案**：
  * “这味药” ➔ 改为 **「该药品」**；
  * “隔 N 天” ➔ 改为 **「间隔天数」** 或 **「每隔多日」**；
  * “进展” ➔ 改为 **「记录」**（与今日、药箱、统计浑然一体）；
  * “统计报表” ➔ 改为 **「用药统计」**；
  * “系统特权自检与保活指引” ➔ 改为 **「后台运行与防漏提醒指引」**。

### 痛点 7：排版与标点规范
* 统一中英文与数字间空格；
* 规范全半角括号与冒号；
* 按钮主动作去掉括号备注与杂乱 Emoji（通知栏保留系统原生干净质感）。

## 四、 核心术语统一对照字典（UX Terminology Dictionary）

| 业务维度 | 现存不规范/口语/生硬词 | 统一标准规范词 | 规范说明与场景 |
| :--- | :--- | :--- | :--- |
| **基础动作** | 吃药 / 该吃药了 | **服药 / 服用 / 该服药了** | 医疗健康标准语境，覆盖所有剂型 |
| **完成操作** | 打卡 / 快捷打卡 | **记录服药 / 确认服药 / 标记已服** | 摒弃考勤打卡心智，强化用药记录 |
| **反悔/纠错** | 改判 / 改判为已服 | **修改状态 / 更改为已服** | 消除裁判法律用语，中性且明确 |
| **回退记账** | 撤销冲正 | **撤销并返还余量 / 撤销恢复** | 消除会计黑话，明确余量联动结果 |
| **库存状态** | 账面 / 账面数量 | **记录余量 / 当前余量** | 用户心智是“系统记录还剩多少” |
| **库存核准** | 盘点校准 / 盘点调整 | **校准库存 / 修正余量** | 清晰表达核实并修正实际数量的意图 |
| **入库补充** | 采购入库 / 购药入库 | **添加库存 / 补充余药** | 消除医院/药企供应链采购用词 |
| **依从率分母** | 已到期 %2$d 次 | **计划 %2$d 次 / 应服 %2$d 次** | **彻底消除药品保质期过期恶性歧义** |
| **未服状态** | 逾期漏服 | **漏服 / 超时未服** | 统计图例与徽标标准表述 |
| **药品量词** | 这味药 | **该药品 / 此药** | 规范现代医药通用量词 |
| **频次类型** | 隔 N 天 | **间隔天数** | 选项枚举消除变量占位符残留 |
| **核心导航** | 进展 / 进展追踪 | **记录 / 服药记录** | 底部四大金刚 Tab 标准化命名 |
| **报表分析** | 统计报表 | **用药统计** | 去后台化、去 ERP 化 |
| **保活指引** | 系统特权自检 | **防漏提醒指南** | 消除“特权”安全担忧，功能导向明确 |

### 6.1 零风险承诺（遵守用户与项目规则）
1. **纯文案资源调整**：本次优化仅涉及 `app/src/main/res/values/strings_*.xml`，**不改变任何业务逻辑、不改变 Room 数据库 schema、不修改 Kotlin 核心架构**。
